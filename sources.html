⛔ Limitations (blockers, not excuses)

  1. No free programmatic X/IG/FB read access. Real-time social listening and historical back-testing need X API Basic ($200/mo) or higher, or a compliant vendor. Instagram/Facebook offer nothing usable for free.
  2. ESPN endpoints are unofficial. They work today and are widely used, but ESPN can change/rate-limit them without notice. The app shows feed status and keeps official manual links everywhere.
  3. Severity is keyword-detected. "Out" in "shootout" style contexts, trade rumors mentioning injuries, etc. can misfire — always confirm via the linked source.
  4. Offseason = thin signal. No games until 2026-10-03; in-game tracking only matters Oct → June. Consequence: the new in-game injury monitor is verified against a completed game's payload structure but untested against a live game — validate on 2026-10-03.
  5. No free feed carries structured "questionable to return" data. QTR in-game alerts therefore depend on the ESPN news layer + the reporter directory (manual review links). See NEXT_STEPS.md.
  6. Scores/alerts live in your browser (localStorage). No server yet, so no cross-device sync, no push when the tab is closed, no shared scorecard.
  7. NBA.com CDN failover is unverifiable from the build environment (TLS-blocked via shell, HTTP 500 via fetch tool — 2026-09-17). Wired defensively; first real browser use will confirm or disable it.
  8. X timeline embeds are best-effort — X rate-limits syndication (observed 2026-09-17 on the deployed site). Alerts never depend on embeds; direct links are always provided.
