🏟️ Identity re-verification — now automatic, not a snapshot

The reporter directory used to be a snapshot: a bio was read once, pasted into assets/js/data.js, and trusted forever. A handle can be re-registered, a bio can change, an account can go quiet — and a page that keeps printing the old claim is worse than no page. So the same evidence is now re-read on a schedule:

  • tools/verify_reporters.js re-runs the exact API call each row cites (app.bsky.actor.getProfiles?actors=…), re-reads the bio, the verification object and the newest post, and also requests all 30 official club channels. No key, no account, no manual input.
  • Red job only when an identity claim breaks: a handle that no longer resolves, or a claimed Bluesky verification object that is gone or invalid. Bio drift and dormancy are written down in data/live/reporter_verify.json — a reporter legitimately changing outlets must be visible, not fatal.
  • The file is rendered on the reporter page (counts, plus each problem row). If it has not run yet, the page says so and presents the session-10 manual pass of 2026-09-18 instead — it never shows a blank panel that reads like "no problems".
  • Run locally: node tools/verify_reporters_test.js (offline, 109 checks) then node tools/verify_reporters.js (needs network). Scheduled daily in .github/workflows/live-audit.yml, and on any change to the registry.

🧬 What “reverse-engineering Basketball Monster” means here

Basketball Monster's player news has no public API and no CORS access, so it cannot be a live feed input — it is the reference model for the wire format instead. As of this session the mapping is much closer than a keyword guess, because the ESPN structured feed supplies the same kinds of fields:

⛔ Limitations (blockers, not excuses)

  1. X / Instagram / Facebook have no free read access. Real-time X listening and X-based historical back-testing need the paid API (~$200/mo). IG/FB offer nothing usable. The free social layer therefore runs on Bluesky, which is a real, working, no-key feed — but it is not X.
  2. Bluesky keyword search is not free either. searchPosts → HTTP 403 unauthenticated (verified). The layer polls a verified allow-list; a first report from an account not on that list will be missed by this layer.
  3. Browser CORS is now proven from the deployed origin itself (2026-09-17, re-confirmed session 8 ~23:15Z). The live GitHub Pages page fetched site.web.api.espn.com/injuries ("via espn-direct · just now", 75 listings) and public.api.bsky.app (13/13 allow-listed accounts browser-direct). The build sandbox still cannot reproduce this (shell HTTPS blocked), so the evidence is the deployed page plus data/audit/latest.json. Fallbacks stay in place — same-origin CI snapshot, then an opt-in labelled relay — and the UI always prints which path served each panel, because a blocking extension, a rate limit or an ESPN policy change can still force one.
  4. The official NBA report has not rolled to 2026-27 (404 verified) and the PDF index returns HTTP 500, so the highest-authority source is currently link-only.
  5. The poller is running, but GitHub cron is best-effort. injury-watch.yml has been executing on schedule since 2026-09-17 (first end-to-end run committed a real snapshot; latest committed: 75 rows / 27 team blocks, 13/13 accounts, errors {}, 2026-09-17). GitHub documents scheduled workflows as best-effort — runs can be delayed under load and are disabled after 60 days of repository inactivity — so the poller is a 10-minute-granularity recorder, not a push channel or a latency guarantee. "First to report" timestamps are only as global as the accounts on the allow-list (see flag about the 4-of-30 team-account ceiling).
  6. ESPN endpoints are unofficial and self-contradicting. They work today; the metadata mismatch between endpoints is documented above. Every alert ships with manual-review links for that reason.
  7. Severity is still classification, not truth. The structured board's status is copied verbatim from ESPN; social posts are classified from wording and an “in-game exit watch” is explicitly unconfirmed.
  8. State is browser-local (localStorage): no cross-device sync, no alerting while the tab is closed, no shared scorecard. The poller's committed history is the only server-side record.
  9. In-game monitor is structure-verified but not live-tested — no NBA game exists until 2026-10-03.
