Reporter directory & evidence ledger

The second verification layer: the people who break or confirm injury news — often before the official designation. This page keeps three identity layers apart, because their evidence quality differs and mixing them is how a directory starts lying: X handles (verified 2026-09-17 in the first pass, each with a link), Bluesky handles (re-verified live 2026-09-17 against the Bluesky public API — including Bluesky's own verification objects and a curated 150-member NBA-writers list), and bylines observed on the injury feed itself — reporters named inside ESPN's injury comments for a specific player, with the quote stored verbatim so it can be re-checked. Only the Bluesky layer can be polled automatically for free, so it is what feeds the live wire; the citation layer carries no asserted handle, because a profile that cannot be read from this environment is not evidence.

Counts below are computed from assets/js/data.js at page load, not typed in — if a row is added or a status changes, these numbers move with it (a hardcoded count on a verification page is exactly the kind of stale claim this project flags).

🟦 Bluesky layer — the free, pollable allow-list

These are the accounts the live social layer actually reads, with the identity evidence for each one. A Bluesky-verified badge means Bluesky's own verification object was present and valid when checked (issuer bsky.app or the outlet's own domain account, e.g. theathletic.com) — which is stronger evidence than an unverified handle. Accounts without it are kept, but labelled.

ℹ Why an allow-list instead of keyword search? Verified 2026-09-17: the Bluesky public API answers getAuthorFeed and searchActorsTypeahead with no key, but returns HTTP 403 for searchPosts unauthenticated. So a keyword firehose is not available for free — which is honestly a quality win: every automated social alert here comes from a named, verified account instead of an anonymous post. The trade-off is documented: a first report from an account not on this list will not be caught by this layer.
